# Saby CRM — Playwright-автотесты

Playwright + TypeScript. Проверяют карточку физического лица, карточку темы
«Лид» и реестры «Контактные лица» и «Темы» на тестовом стенде Saby:
визуальные эталоны, функциональные сценарии, а также создание и редактирование
временных ФЛ и темы.

## Структура

```
tests/
  support/
    constants.ts     # URL, учётные данные, UUID темы
    auth.ts          # вход через SSO
    global-setup.ts  # однократный логин, сохранение storageState
    ui.ts            # хелперы: реестры/темы/карточки, создание, заполнение, удаление
    theme-dynamic.css # скрытие динамических данных на скриншотах темы
  test-1.spec.ts     # визуальные проверки карточки ФЛ
  test-2.spec.ts     # визуальные проверки карточки темы
  test-3.spec.ts     # smoke-проверка страницы входа
  test-4.spec.ts     # функциональные проверки карточки ФЛ
  test-5.spec.ts     # функциональные проверки карточки темы
  test-6.spec.ts     # открытие карточки ФЛ по ссылке в новой вкладке
  test-7.spec.ts     # реестр «Контактные лица»: поиск и фильтры
  test-8.spec.ts     # реестр «Темы» и окна счётчиков
  test-9.spec.ts     # создание/заполнение ФЛ и редактирование полной карточки
  test-10.spec.ts    # новая тема: изменение этапа «Новый»
  *-snapshots/       # эталонные скриншоты
playwright.config.ts
COVERAGE.md          # матрица покрытия и непокрытые области
```

## Запуск

```bash
npm install
npx playwright install chromium
npm test
```

Перед тестами `global-setup` один раз логинится и сохраняет сессию в
`playwright/.auth/user.json`. Все тесты стартуют уже авторизованными, поэтому
логин не повторяется в каждом тесте.

Полезные команды:

```bash
npm run test:headed     # с открытым браузером
npm run test:ui         # интерактивный режим
npm run test:update     # пересоздать все эталонные скриншоты
npm run report          # открыть HTML-отчёт
```

## CI (GitHub Actions)

В `.github/workflows/playwright.yml` подготовлен workflow для запуска suite на
`windows-latest`: установка зависимостей, Chromium и `npm test`. После прогона
в артефакты GitHub Actions публикуются:

- `playwright-report` — HTML-отчёт;
- `test-results` — скриншоты, трейсы и другие материалы упавших тестов.

Для запуска добавьте в настройках репозитория secrets `SABY_LOGIN` и
`SABY_PASSWORD`. Если стенд Saby доступен только из корпоративной сети,
замените `runs-on: windows-latest` на метку self-hosted Windows-раннера.

## Учётные данные и тестовые данные

По умолчанию используются учётная запись и тема со стенда. Их можно переопределить
переменными окружения:

| Переменная | По умолчанию |
|---|---|
| `SABY_LOGIN` | `screencrm` |
| `SABY_PASSWORD` | `screencrm!44` |
| `SABY_THEME_UUID` | `01a03962-b5ad-787c-a0f4-e78c18ca888a` |
| `SABY_THEME_TYPE` | `Лид` |

Пример (PowerShell):

```powershell
$env:SABY_LOGIN = 'user'
$env:SABY_PASSWORD = 'password'
npm test
```

## Скриншоты

- Эталоны сняты для **Chromium / Windows**. Для другого браузера или ОС нужны
  отдельные baseline-файлы, поэтому в конфиге оставлен только Chromium.
- Динамические данные (счётчик сделок, номера этапов, проценты, фильтр) скрываются
  через CSS перед снимком карточки темы. Это сохраняет геометрию страницы и убирает
  ложные падения из-за изменения данных.
- В карточке ФЛ маскируется возраст (зависит от текущей даты), в визитке — сумма
  в блоке продаж.
- При осознанном изменении интерфейса обновляйте эталон:
  `npm run test:update`, затем просмотрите diff в HTML-отчёте.

## Что проверяется

- `test-1`: визуальные проверки — пустая мини-карточка ФЛ; полная карточка
  (Параметры, Покупки, Активности); заполненная карточка; визитка из списка
  договоров.
- `test-2`: визуальные проверки 11 разделов карточки темы «Лид».
- `test-3`: доступность страницы входа Saby.
- `test-4`: функциональные проверки карточки ФЛ — структура мини-карточки,
  закрытие без сохранения, последовательное переключение вкладок, данные
  заполненного клиента и визитки.
- `test-5`: функциональные проверки темы — полнота меню, содержимое воронки,
  параметры, роли, ссылки верхней навигации и последовательный обход разделов.
- `test-6`: открытие карточки ФЛ по ссылке, скопированной из живой карточки,
  в новой вкладке; отдельно проверяется команда «В новой вкладке». Ссылка
  читается из буфера обмена, а не задаётся в тесте.
- `test-7`: реестр «Контактные лица» — активный раздел, список с телефонами и
  email, поиск по фамилии, фильтры по полу и возрасту.
- `test-8`: реестр «Темы» — группы, строки тем и папок, колонки счётчиков,
  переход в карточку темы и три окна счётчиков строки «Тема для статистики»
  («Просроченные», «В работе», «Новый, Новые») с проверкой списка сделок и
  закрытия.
- `test-9`: два сценария с временной ФЛ — заполнение мини-карточки (ФИО, телефон,
  примечание, дата рождения, пол, адрес, паспорт, место рождения) с проверкой
  в полной карточке и изменением примечания; создание ФЛ с переходом в полную
  карточку, заполнением основных полей, сохранением и повторным открытием.
- `test-10`: создание временной темы «Продажи», проверка этапа «Новый», открытие
  карточки этапа, изменение его названия, сохранение темы, повторное открытие
  и удаление.

Сценарии `test-1` — `test-8` только читают данные. `test-9` и `test-10` создают
временные записи с уникальными именами и удаляют их после проверки; `afterEach`
удаляет запись и при падении теста, чтобы не засорять общий стенд.
Матрица покрытия и список непокрытых областей — в `COVERAGE.md`.
