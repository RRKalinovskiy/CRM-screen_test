# Копия suite для стенда test

Это отдельный worktree ветки `test-stand`, настроенный на `https://test-online.sbis.ru`.
Основной репозиторий и ветка `main` не затрагиваются. Отличия от `main`
перечислены ниже; общее описание suite — в `README.md`, матрица покрытия —
в `COVERAGE.md`.

## Настройки стенда

| Параметр | Значение по умолчанию |
|---|---|
| `APP_ORIGIN` | `https://test-online.sbis.ru` |
| `AUTH_URL` | `https://test-sso.saby.ru/auth-online/test-online.sbis.ru/?ret=test-online.sbis.ru/page/crm-unified-contacts` |
| `APP_ALIAS_ORIGIN` | тот же хост в зоне `saby.ru` (`https://test-online.saby.ru`) |
| `SABY_THEME_UUID` | `5440011c-8d41-11e7-adf1-005056b7473e` |
| `SABY_THEME_TYPE` | `Лид` |
| Логин | те же `SABY_LOGIN` / `SABY_PASSWORD`, что и на fix |
| Пустой пользователь | по умолчанию **не** логинится: на стенде test профиля `Пустой44` нет |

Стенд можно переопределить без правки кода:

```powershell
$env:SABY_APP_ORIGIN='https://test-online.sbis.ru'
$env:SABY_AUTH_URL='https://test-sso.saby.ru/auth-online/test-online.sbis.ru/?ret=test-online.sbis.ru/page/crm-unified-contacts'
```

Значения логина и пароля хранятся только в переменных окружения или секретах
CI и в документации не публикуются.

## Тема и данные test

- Тема стенда — «Продажа товаров и услуг», `SABY_THEME_UUID` =
  `5440011c-8d41-11e7-adf1-005056b7473e`, тип `Лид`. Старое значение UUID
  из main (`01a03962-…`) на test не открывается.
- `test-2` снимает 11 эталонов этой темы; `test-5` проверяет её этапы
  «Новый», «Знакомство», «Коммерческое предложение», «Оплата», «Отгрузка»,
  «Товар доставлен», «Сделка не состоялась» и итоги.
- В реестре тем (`test-8`) на test доступна одна группа «Продажи» и одна
  демо-тема «Продажа товаров и услуг»; папок, групп «Аудит»/«Обслуживание»
  и счётчиков у неё нет.
- `test-10` создаёт временную тему «Продажи» через реестр, привязанный к UUID
  стенда test, и удаляет её после проверки.
- `test-15` и `test-16` используют `THEME_NAME = «Продажа товаров и услуг»`
  из `tests/support/theme-mini-card.ts`.
- `test-7` проверяет контакты «Сизов Виктор Генадьевич», «Горохов Евгений
  Олегович» и «Большие Данные Физик»; у Сизова заполнен телефон, но не email.
- Нет контакта «Проверка Карточки Физика»: `test-14` использует демо-клиента
  «Сизов Виктор Генадьевич». Ожидаемые значения в
  `tests/support/new-individual-card.ts` соответствуют его карточке: телефон
  `+7 (953) 648-57-58`, сайт `vorota-siz.ru`, дата рождения `12.05.1976`,
  адреса в Ярославской области и Костроме, паспорт.
- У Сизова нет продаж, поэтому в `test-14` пропущены проверки плашки периода
  и повторной загрузки списка продаж; вместо 20 строк проверяется, что вкладка
  «Покупки» построилась.
- Нет профиля `Пустой44`: `SABY_SETUP_EMPTY` по умолчанию выключен,
  `playwright/.auth/empty44.json` не создаётся.
- В импорте (`test-17`) уведомление об ошибке на test не содержит прямой ссылки
  на файл: файл скачивается из «Журнал выполнения» → «Скачать файл» по
  подписанной ссылке `test-go`. Хелпер поддерживает оба варианта — прямую ссылку
  в уведомлении (fix) и журнал (test).
- Автосопоставление столбцов при импорте на test может отличаться от fix,
  поэтому проверяется количество сопоставленных столбцов и выбранные поля,
  а не жёсткий список.

## Новые контролы карточки ФЛ

На стенде test карточка ФЛ открывается в новой разметке `.crm_IndividualCardNew`.
Старая разметка `.crm_IndividualCard` оставлена как fallback: хелперы
поддерживают обе, поэтому сценарии работают на fix и на test без ветвления
по стенду. Основные отличия — в тестовых данных и пропущенных проверках.

Хелперы в `tests/support/ui.ts` и `tests/support/new-individual-card.ts`
используют:

- корень `.crm_IndividualCardNew` (вместо `.crm_IndividualCard__tabsArea`);
- `data-qa="crm_IndividualCard__edit"` и `crm_IndividualCard__saveButton`
  для перехода в редактирование и сохранения;
- `data-qa="pd-componentsBirthDateInput"` — дата рождения;
- `data-qa="pd-componentsGender"` — пол;
- контакты (телефон, примечание) редактируются отдельным контролом, а не
  inline-полем `.cd-MultipleInput__field_Value`;
- вкладки ищутся по `[name="tabparams"]`, `[name="tabpurchases"]`,
  `[name="tabactivity"]` внутри корня карточки;
- после удаления карточка остаётся открытой в состоянии «Клиент удалён»,
  поэтому хелпер очистки закрывает её и перезагружает реестр.

Клик по контакту в реестре выполняется по строке `[data-qa="row"]` и заголовку
контакта, а не по произвольному тексту: в плиточной выдаче то же имя встречается
в заголовке категории, клик по которому не открывает карточку.

## CI

`test-sso.saby.ru` не резолвится с GitHub-hosted раннеров, поэтому workflow
`Playwright (test stand)` переведён в ручной запуск (`workflow_dispatch`).
Для запуска нужен self-hosted Windows-раннер с доступом к корпоративной
сети/VPN; в workflow сейчас указан `runs-on: windows-latest`, его нужно
заменить на метку такого раннера. Для GitHub-hosted раннера потребуется
проброс DNS/VPN до стенда test.

Job пустого пользователя (`empty-contacts`) в этой ветке отключён (`if: false`),
потому что профиля `Пустой44` на test нет. Основной job выполняет
`npx playwright test --grep-invert "@empty-user"` — 98 тестов; в прогоне
на test это 84 passed и 14 skipped.

## Запуск

```powershell
npm ci
npx playwright install chromium

# основной набор без сценариев пустого пользователя
npx playwright test --grep-invert "@empty-user"

# отдельные наборы
npx playwright test tests/test-14.spec.ts   # новая карточка ФЛ
npx playwright test tests/test-17.spec.ts   # импорт ФЛ из Excel

# пересоздать эталоны после осознанного изменения интерфейса
npx playwright test tests/test-1.spec.ts --update-snapshots=all
npx playwright test tests/test-2.spec.ts --update-snapshots=all
```

`npm test` в этой ветке запускает основной набор без `@empty-user`; для запуска
всего suite используйте `npm run test:all`. Сценариям `@empty-user` нужен профиль
`Пустой44` на стенде test и `SABY_SETUP_EMPTY=1`.

- `tests/support/constants.ts` — origin, SSO и алиас ссылок вынесены в env
  с дефолтами test; `SABY_THEME_UUID` указывает на тему test
  `5440011c-8d41-11e7-adf1-005056b7473e`; добавлен `APP_LINK_ORIGINS` для
  проверки ссылок на `sbis.ru` и `saby.ru`.
- `tests/support/theme-mini-card.ts` — `THEME_NAME = «Продажа товаров и услуг»`.
- `tests/support/auth.ts` — проверка домена после входа берётся из `APP_ORIGIN`.
- `tests/support/ui.ts` — корень карточки ФЛ `.crm_IndividualCardNew` с fallback
  на старую разметку, новые кнопки редактирования/сохранения, клик по строке
  контакта, удаление с закрытием состояния «Клиент удалён».
- `tests/support/new-individual-card.ts` — проверка SSO по `SSO_HOST`,
  демо-клиент «Сизов Виктор Генадьевич» и его данные.
- `tests/support/individual-import.ts` — устойчивое сопоставление столбцов,
  ожидание результата текущего импорта, проверка новой карточки и скачивание
  файла ошибок через журнал.
- `tests/support/global-setup.ts` — пустой пользователь по умолчанию выключен.
- `test-1` — фиксация режима «Колонки» перед эталоном и `skip` визитки.
- `test-2` — эталоны пересняты под тему test.
- `test-4` — данные Сизова и `skip` визитки.
- `test-5`, `test-7`, `test-8`, `test-10`, `test-15`, `test-16` — ожидания
  под тему «Продажа товаров и услуг», её этапы, UUID и контакты test.
- `test-6`, `test-17` — адаптация под новую карточку, алиас ссылок и журнал
  ошибок импорта.
- `test-8` — три теста счётчиков пропущены.
- `test-13` — весь файл пропущен через `test.describe.skip`.
- `test-14` — два теста продаж пропущены, остальные проверки идут на Сизове.
- `test-15` — мини-карточка темы в сделке пропущена.
- `tests/test-1.spec.ts-snapshots/`, `tests/test-2.spec.ts-snapshots/` —
  эталоны перегенерированы под test-stand.
- `.github/workflows/playwright.yml` — ручной запуск, job пустого пользователя
  отключён.
