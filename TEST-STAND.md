# Копия suite для стенда test

Это отдельный worktree ветки `test-stand`, настроенный на `https://test-online.sbis.ru`.
Основной репозиторий и ветка `main` не затрагиваются. Отличия от `main`
перечислены ниже; общее описание suite — в `README.md`, матрица покрытия —
в `COVERAGE.md`.

## Настройки стенда

| Параметр | Значение по умолчанию |
|---|---|
| `APP_ORIGIN` | `https://test-online.sbis.ru` |
| `AUTH_URL` | `https://test-sso.saby.ru/auth-online/test-online.sbis.ru/?ret=test-online.sbis.ru/page/crm-unified-contacts` |
| `APP_ALIAS_ORIGIN` | тот же хост в зоне `saby.ru` (`https://test-online.saby.ru`) |
| `SABY_THEME_UUID` | `5440011c-8d41-11e7-adf1-005056b7473e` |
| `SABY_THEME_TYPE` | `Лид` |
| Логин | те же `SABY_LOGIN` / `SABY_PASSWORD`, что и на fix |
| Пустой пользователь | по умолчанию **не** логинится: на стенде test профиля `Пустой44` нет |

Стенд можно переопределить без правки кода:

```powershell
$env:SABY_APP_ORIGIN='https://test-online.sbis.ru'
$env:SABY_AUTH_URL='https://test-sso.saby.ru/auth-online/test-online.sbis.ru/?ret=test-online.sbis.ru/page/crm-unified-contacts'
```

Значения логина и пароля хранятся только в переменных окружения или секретах
CI и в документации не публикуются.

## Новые контролы карточки ФЛ

На стенде test карточка ФЛ открывается в новой разметке `.crm_IndividualCardNew`.
Старая разметка `.crm_IndividualCard` оставлена как fallback: хелперы
поддерживают обе, поэтому сценарии работают на fix и на test без ветвления
по стенду. Основные отличия — в тестовых данных и пропущенных проверках.

Хелперы в `tests/support/ui.ts` и `tests/support/new-individual-card.ts`
используют:

- корень `.crm_IndividualCardNew` (вместо `.crm_IndividualCard__tabsArea`);
- `data-qa="crm_IndividualCard__edit"` и `crm_IndividualCard__saveButton`
  для перехода в редактирование и сохранения;
- `data-qa="pd-componentsBirthDateInput"` — дата рождения;
- `data-qa="pd-componentsGender"` — пол;
- контакты (телефон, примечание) редактируются отдельным контролом, а не
  inline-полем `.cd-MultipleInput__field_Value`;
- вкладки ищутся по `[name="tabparams"]`, `[name="tabpurchases"]`,
  `[name="tabactivity"]` внутри корня карточки;
- после удаления карточка остаётся открытой в состоянии «Клиент удалён»,
  поэтому хелпер очистки закрывает её и перезагружает реестр.

Клик по контакту в реестре выполняется по строке `[data-qa="row"]` и заголовку
контакта, а не по произвольному тексту: в плиточной выдаче то же имя встречается
в заголовке категории, клик по которому не открывает карточку.

## CI

`test-sso.saby.ru` не резолвится с GitHub-hosted раннеров, поэтому workflow
`Playwright (test stand)` переведён в ручной запуск (`workflow_dispatch`).
Для запуска нужен self-hosted Windows-раннер с доступом к корпоративной
сети/VPN; в workflow сейчас указан `runs-on: windows-latest`, его нужно
заменить на метку такого раннера. Для GitHub-hosted раннера потребуется
проброс DNS/VPN до стенда test.

Job пустого пользователя (`empty-contacts`) в этой ветке отключён (`if: false`),
потому что профиля `Пустой44` на test нет. Основной job выполняет
`npx playwright test --grep-invert "@empty-user"` — 98 тестов; в прогоне
на test это 96 passed и 2 skipped.

## Запуск

```powershell
npm ci
npx playwright install chromium

# основной набор без сценариев пустого пользователя
npx playwright test --grep-invert "@empty-user"

# отдельные наборы
npx playwright test tests/test-14.spec.ts   # новая карточка ФЛ
npx playwright test tests/test-17.spec.ts   # импорт ФЛ из Excel

# пересоздать эталоны после осознанного изменения интерфейса
npx playwright test tests/test-1.spec.ts --update-snapshots=all
npx playwright test tests/test-2.spec.ts --update-snapshots=all
```

`npm test` в этой ветке запускает основной набор без `@empty-user`; для запуска
всего suite используйте `npm run test:all`. Сценариям `@empty-user` нужен профиль
`Пустой44` на стенде test и `SABY_SETUP_EMPTY=1`.
